# v0.11.0

## Highlights

This release adds an opt-in dynamic project policy to the Infisical MCP
management surface. Each request resolves a trusted client context, reloads the
private Host policy, and intersects Host-allowed projects with the current
Infisical machine identity's project listing. Policy or identity-list failures
deny the request. The policy does not enroll identities or change Infisical
permissions.

## Added

- Configure trusted context-to-project mappings and optional cross-project
  targeting in an existing Host enrollment policy.
- Apply per-project `identity`, `deny`, `read-only`, or `limited` modes. Limited
  secret and folder operations require exact environment and path-prefix
  constraints; limited environment creation is restricted to listed slugs.
- Keep the feature disabled by default. Existing MCP registrations, static
  project allowlists, and the live `doctor-repair` scope remain unchanged.

## Migration

No migration is required for existing installations. To use dynamic policy,
start a separately approved MCP process with `-manage -project-policy
/absolute/path/to/policy.json -client-context CONTEXT`. The policy path must be
the private Host enrollment policy, and the context must exist in its
`mcpAccess.contexts` mapping. Do not add these flags to the live MCP
registration without explicit activation approval.
