# v0.11.1

## Highlights

- Infisical MCP capability discovery now reflects the running process's
  management and deployment configuration.
- Dynamic policy denials return a clear, sanitized error.

## Changed

- Capability output separates supported management operations, tool exposure,
  credential configuration, project-creation gate, profile availability,
  permission status, and test coverage. Discovery never claims that live
  upstream permissions have been verified.
- MCP initialization advertises the released version. Capability output includes
  the build's source commit and modified-source flag for connection verification.

## Fixed

- Map dynamic-policy denial to `policy_denied`. Keep upstream authentication
  and permission failures, missing resources, invalid response schemas, and
  transport failures distinct without exposing secret values or target details.

## Configuration

- No configuration change is required. The current dynamic-policy registration
  still denies `project.create`, and deployment remains opt-in through a trusted
  profile directory and `KUCHDESK_DEPLOY_ENABLED=true`.

## Installation

- The Host tools archive targets this Mac's `darwin/arm64` platform and includes
  MCP, Host Bridge, Host Agent, Infisical CLI, enrollment, Doctor, and deploy tools.
  Verify the archive with the published `SHA256SUMS` before installation.
- Restart the affected connection or process after replacement. Keep existing
  MCP scope, trusted context, private policy, credentials, and TLS configuration.
- Kubernetes agent and controller source, chart, manifests, and dependencies are
  unchanged since v0.11.0; this release does not require their redeployment.
