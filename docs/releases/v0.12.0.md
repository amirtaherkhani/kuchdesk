# v0.12.0

## Highlights

Verify secret writes end to end through MCP without exposing secret values.

## Added

- `infisical_verify_secret_write`, available with `-scope all -manage`, creates
  a random disposable secret in one explicit project/environment/path. It
  compares markers internally after create and update, rejects a different
  marker, deletes the fixture, and confirms absence.
- Verification returns comparison/cleanup flags and an owned fixture name;
  it accepts neither an existing name nor an expected value. Values, tokens
  and value hashes stay outside MCP responses and logs.

## Configuration

Confirm with `secret.verify_write:<projectId>/<environment><path>`. Existing
create/get/update/delete policy must allow the scope, and upstream permissions
must allow each request, including value read. Permissions are not granted by
this release. Normal `secret.get` remains metadata-only. Doctor scopes and
Host Bridge/Kubernetes HTTP APIs do not expose the new verifier.

The operation has a 45-second limit and cleanup may take another 25 seconds.
An interrupted request attempts cleanup with an independent bounded context;
process termination or revoked permissions can leave a fixture. A failed
cleanup reports its exact name for scoped operator cleanup.

## Installation

The Host bundle targets Darwin ARM64. Build metadata and checksums accompany
the artifacts. Restart the affected MCP connection after installation and
check `infisical_capabilities.build`; replacing the file alone does not update
an existing process. Deployment stays disabled without explicit opt-in and
profiles. Dynamic policy continues to deny project creation.

The shared Host command authorization path is reused; Host Bridge and Host
Agent require relevant checks/install verification. Kubernetes Agent source,
controllers and chart are unchanged, so no Kubernetes Agent redeploy is needed.
