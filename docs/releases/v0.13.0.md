# v0.13.0

## Highlights

Development project provisioning, permission administration, explicit
secret-value access, and grouped writes are available through the Host-backed
MCP path when their separate policy and upstream permissions are enabled.

## Added

- `project.create` accepts a stable request ID, optional native slug,
  description, template, and default-environment choice. Omitting slug uses
  Infisical's generated slug. A Development-only request creates native
  `Development/dev` and returns the actual ID, slug, and environments.
- `identity.create` and `identity.delete` manage prefix-limited disposable
  no-access identities with private ownership receipts. Existing `role.*` and
  `membership.*` commands administer project permissions.
- `infisical_read_secret_values` returns individual or bounded collection
  values at an exact project/environment/path. `secret.get` stays metadata-only.
- `infisical_group_secret_writes` provides a value-free plan and sequential
  explicit create/update/delete actions with version checks and per-key status.
- A stateless development smoke source/chart supports a reviewed private
  deployment profile.

## Changed

- MCP capabilities distinguish implementation and exposure from effective
  policy, upstream permissions, and live test evidence.

## Fixed

- Dynamic project creation no longer requires a membership in a project that
  does not exist. Existing-project operations retain the Host-policy and
  identity-list intersection.
- A nonempty dynamic MCP project map now denies and hides identity-visible
  projects without an explicit rule, so a project-creation prefix does not
  expand access to unrelated projects.

## Configuration

Enable project creation with `-allow-project-create` and a trusted dynamic
context containing `allowProjectCreate:true`, `allowCrossProject:true`, and a
development `projectNamePrefix`. Enable disposable identity administration
separately with `-allow-identity-admin`, `allowIdentityAdmin:true`, and an
`identityNamePrefix`. Upstream organization and project authority is still
required. Use stable request IDs and exact write confirmations.

Set `KUCHDESK_DEPLOY_PROFILE_DIR` to a private absolute directory containing
only reviewed development profiles and `KUCHDESK_DEPLOY_ENABLED=true` in the
trusted MCP process environment. Each profile binds source, context,
namespace, release and image repository. Reconnect Codex after installing
the new MCP binary or changing its startup environment.

Value-read responses intentionally enter MCP and conversation context. Keep
them out of logs and final reports. Imports, recursive folders and reference
expansion are excluded. Group writes are sequential and can partially apply;
Infisical v0.151.0 has no atomic version precondition against external
writers, so reread metadata before retrying failed keys.

Applications and tests continue to retrieve ENV through their existing
Infisical CLI, OIDC, or Operator path. The Kubernetes identity remains
read-only; the Host Bridge and Kubernetes Agent are not given a value-read or
administrative network API by this release.
